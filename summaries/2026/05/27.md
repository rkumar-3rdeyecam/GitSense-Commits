1.  **AWS Service Integration**: A strong recurring pattern is the extensive use of AWS SDK clients (DynamoDB, Kinesis, S3, SQS, SSM) across `Events.ts` and `Intake.ts` for data persistence, streaming, and configuration management.
2.  **Event-Driven Architecture**: The system is heavily event-driven, processing events from Kinesis streams (`Events.ts`, `preprocessor.ts`), DynamoDB streams (`command.ts`), and API Gateway (`Intake.ts`). Events are also published to EventBridge (`command.ts`).
3.  **Command Pattern**: The `command.ts` and `interfaces.ts` files define a command processing flow involving `UduCommand` objects stored in DynamoDB, initiated by EventBridge events, and updated based on UDU responses.
4.  **Error Handling**: Consistent error handling includes logging errors (`console.error`), throwing `FatalIngestError` for critical issues, and writing problematic messages to a Dead Letter Queue (DLQ) for non-fatal errors (`Events.ts`, `Intake.ts`, `preprocessor.ts`).
5.  **Interface-Driven Development**: The `interfaces.ts` file plays a central role, defining the structure of various data objects, events, and the contracts for `IEvents` and `IPreprocessor` implementations.
6.  **Environment Variables**: Reliance on `process.env` for configuration (e.g., `DEAD_LETTER_QUEUE`, `RAW_STREAM`, `TEMP_MEDIA_BUCKET`, `EVENT_BUS`) is consistent across all Lambda functions.
7.  **S3 Object Management**: Frequent operations involve reading, writing, and copying objects to and from S3 buckets, often for temporary storage or media files.
8.  **Evolution of `UduCommand` and `lookupMacAddress`**: There are several iterations and reversals regarding the `UduCommand` interface's `tenantIdDivisionId` field and the return type of `IEvents.lookupMacAddress` in `interfaces.ts` and its usage in `command.ts`. This suggests ongoing refinement or attempts to integrate division ID more directly into command handling, followed by a rollback or simplification.
    *   Initially `UduCommand` had `tenantIdDivisionId?: string;`.
    *   Then `UduCommandWithTenantDivisionId` and later `UduCommandWithDivisionId` were introduced and removed.
    *   The `lookupMacAddress` function's return type changed from `string` to `{ macAddr: string, divisionId: string }` and then back to `string | undefined`.
    *   The `addCommand` function's parameters (`tenantIdDivisionId` / `divisionId`) were added and subsequently removed. This indicates a period of experimentation or incomplete feature integration related to how tenant and division IDs are managed with MAC addresses and commands.
9.  **No Changes for Many `Events.ts` Timestamps**: Several `Events.ts` entries show identical code, indicating either frequent saving, minor non-code changes, or automated updates that didn't alter the functional logic.
