This stack is responsible for deploying a microservice that manages assets and devices, primarily using AWS Lambda functions.

Key aspects of the stack definition include:

*   **VPC Integration**: It looks up an existing VPC (`ArkVpc`) by name to deploy resources within a defined network environment.
*   **Configuration Management**: Vital identifiers such as private API Gateway ID, name, stage, URL, and KMS key ARN are retrieved from AWS Systems Manager Parameter Store, promoting flexible and secure configuration. ElastiCache connection details are also sourced from Parameter Store.
*   **Security Policies**: IAM policies are defined to allow connections to ElastiCache and decryption operations via KMS, ensuring secure access to these services.
*   **Network Security**: A dedicated `LambdaSecurityGroup` is created and associated with all deployed Lambda functions, enforcing network access controls within the VPC.
*   **Lambda Function Deployment**: The stack extensively utilizes a `CrudLambdaPattern` from the `@cloud-arkdev/cdk-patterns` library to deploy numerous Lambda functions. Each Lambda is configured with:
    *   A unique function name, entry point (script), and handler.
    *   Environment variables injecting DynamoDB table names (`TABLE_ASSET`, `TABLE_DEVICE`) and the private API URL.
    *   Specific read or read/write permissions to DynamoDB tables (`assetTablePattern.table` or `deviceTablePattern.table`) from an injected `AssetDeviceStorageStack`.
    *   Association with the defined VPC, API Gateway ID, and security group.

**Specific Lambda functions deployed using this pattern include:**

*   CRUD operations for assets and devices (`assetsCrudLambdaPattern`, `devicesCrudLambdaPattern`).
*   Bulk subscription functionalities for asset products and use cases (`assetsProductsBulkSubscriptionLambdaPattern`, `assetsUsecasesBulkSubscriptionLambdaPattern`).
*   Retrieval of asset products and use cases (`assetProductsLambdaPattern`, `assetUsecasesLambdaPattern`).
*   Asset reporting and commenting (`getAssetsAsCSVLambdaPattern`, `assetCommentInfoLambdaPattern`, `createAssetCommentLambdaPattern`, `updateAssetCommentLambdaPattern`, `createAssetCSVLambdaPattern`).
*   Asset-device relationship management, including reassigning devices to assets or reassigning multiple devices (`reassignDevicesLambdaPattern`, `reassignDeviceAssetLambdaPattern`).
*   Device firmware management (`firmwareUrlByMacAddressLambdaPattern`, `saveDesiredFirmwareForDeviceLambdaPattern`, `deviceFirmwareRollbackLambdaPattern`).
*   GeoFence updates for assets (`updateAssetForGeoFenceLambdaPattern`).
*   Device division movements (`moveDevicesDivisionLambdaPattern`).
*   **Cross-Table Permissions**: Explicit IAM policies are added to `assetsCrudLambdaPattern` to allow querying the device table, and `reassignDevicesLambdaPattern` and `reassignDeviceAssetLambdaPattern` are granted read/write access to both asset and device tables.

**Patterns and Recurring Elements:**

*   **Modular Lambda Deployment**: The `CrudLambdaPattern` is a dominant recurring element, standardizing the deployment of various API-driven Lambda functions, each interacting with DynamoDB.
*   **DynamoDB as Primary Data Store**: Nearly all Lambda functions interact with either the asset or device DynamoDB tables, which are passed in from a `storageStack`.
*   **Externalized Configuration**: Extensive use of AWS Parameter Store for retrieving API endpoints, security keys, and service ARNs.
*   **VPC-Scoped Resources**: All core compute (Lambda) and networking components are deployed within a specified VPC, indicating a private and secure network architecture.
